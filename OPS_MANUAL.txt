FREYJA OPERATIONS MANUAL
=========================

Purpose
-------
This is the practical handoff guide for operating Freyja without relying on
one person to remember the stack. It documents the live system as of
2026-09-29. It intentionally contains no passwords, API keys, bot tokens, or
private SSH keys.

Network rule
------------
All of these services are intended for the private Tailscale/VPN network.
Do not expose them to the public Internet. A reachable URL does not grant
permission to use a consequential tool: Iris Core policy and per-agent MCP
credentials remain the tool boundary.

3. CANONICAL REQUEST PATH
-------------------------

Web chat:
  LibreChat named agent
    -> Vulcan Nexus chooses/serves the approved local model
    -> Iris Core MCP supplies authorized tools and scoped memory operations
    -> MacAgent, Home Assistant, OpenCode, Apple services, or other tools

Messaging chat:
  Discord connector
    -> Director resolves identity and delivery policy
    -> same canonical named agent identity
    -> Iris Core for tools

Important: Director is channel identity/delivery policy. It must not become a
second model-response wrapper for LibreChat, Open WebUI, or LobeHub chats.

5. FIRST-LINE HEALTH CHECKS
---------------------------

From any VPN-connected machine:

  python3 scripts/freyja-live-readiness.py
  curl -fsS http://100.94.80.21:8512/health
  curl -fsS http://100.115.228.56:8510/health
  curl -fsS http://100.94.80.21:11434/api/tags

Browser checks:
  1. Open LibreChat and verify the named-agent selector appears.
  2. Start a fresh chat with Cloyd and ask a simple non-tool question.
  3. Ask Agent 47 for its role; do not begin with an infrastructure change.
  4. If Discord is being checked, send a short text-only DM to Freyja or
     Cloyd and confirm the response identifies the expected agent.

What good looks like:
  - Web portal loads.
  - Named agent produces a written response, not only a tool trace.
  - Tool requests report the correct named identity.
  - Core health succeeds.
  - No password, token, or internal secret appears in chat, logs, or commits.

`scripts/freyja-live-readiness.py` is the repeatable no-secret baseline. It
expects Nexus to reject an unauthenticated model-list request; that 401 proves
the gateway is reachable and still protected.


6. OPERATOR COMMANDS
--------------------

Vulcan Director (run as the `joe` desktop user; no sudo):
  systemctl --user status freyja-paralegal-director.service --no-pager
  journalctl --user -u freyja-paralegal-director.service -n 200 --no-pager
  systemctl --user restart freyja-paralegal-director.service

Iris launch agents (run on Iris):
  launchctl print gui/$(id -u)/com.freyja-os.core
  launchctl print gui/$(id -u)/com.freyja-os.core-mcp
  launchctl print gui/$(id -u)/com.freyja-os.discord-dm-connector
  launchctl print gui/$(id -u)/com.freyja-os.discord-dm-connector-freyja

Atlas containers (run on Atlas):
  docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
  docker compose ls

Use a targeted restart only after identifying the failed service. Never use a
broad container prune, delete volumes, reset a git worktree, or rotate secrets
as a first troubleshooting step.


7. COMMON FAILURE ROUTES
------------------------

LibreChat opens but no named agents/tools:
  - Verify Atlas containers are running.
  - Verify Nexus and Iris Core health endpoints.
  - Review LibreChat logs for MCP initialization failures.
  - Confirm the profile definition at config/librechat-family-agents.yaml has
    not been changed without updating LibreChat.

Agent gives a trace but no written answer:
  - This is normally an inference/model response issue, not proof that tools
    worked. Retry once with a simple text-only question.
  - Check Nexus availability and the selected agent's preset.
  - Review Director only for channel traffic; portal chat should go direct to
    Nexus, not through a Director response wrapper.

Tool call fails:
  - Check Iris Core health first at its Tailscale address (`:8510`); it is not
    intended to listen on 127.0.0.1.
  - Confirm the agent is using its own MCP identity; do not borrow another
    agent's token or downgrade its scope to make a test pass.
  - For Apple-specific work, check MacAgent status on Iris.

Agent Smith needs attention:
  - Check `http://100.115.228.56:8000/agent-runs/api/runtime/health` and
    `http://100.115.228.56:8000/agent-runs/api/status`.
  - Treat this as read-only evidence. Smith is not authorized to repair a
    service unless an operator explicitly approves the specific action.
  - Follow `docs/operations/agent-smith-watchdog.md` before enabling alerts.

Discord fails:
  - Verify the connector launch agent on Iris.
  - Check the private runtime environment locally on Iris; never print it.
  - Confirm the DM resolves to Freyja or Cloyd, not a generic fallback.
  - Read docs/discord/family-discord-runbook.md before adding an identity.

Before any change:
  1. State the desired outcome and affected machine/service.
  2. Check the current service health and git status.
  3. Make the smallest reversible change.
  4. Verify the affected endpoint and a real named-agent response.
  5. Commit documentation/configuration updates; never commit secrets.


9. SECURITY / HANDOFF RULES
---------------------------

  - Keep credentials in private host environment files or approved secret
    stores. Use file mode 0600 where applicable.
  - Do not paste secrets into Discord, LibreChat, LobeHub, Open WebUI, git,
    issue trackers, or this manual.
  - A VPN is a network boundary, not a replacement for per-agent tool policy.
  - Require explicit approval for calendar writes, home control, destructive
    shell actions, credential changes, and agent-wide memory sharing.
  - Preserve per-person agent memory boundaries. Do not merge private chats
    into household memory by convenience.
